RESEARCH NOTE
Topic: Software Development Philosophy
Source: *The Pragmatic Programmer* — Andrew Hunt & David Thomas (20th Anniversary Ed.)
Date: 2025-01-15

**Central Claim:** Professional software development is a craft requiring deliberate habits, continuous learning, and taking ownership — not just technical knowledge.

**Key Findings:**
- **DRY Principle** — "Don't Repeat Yourself." Every piece of knowledge should have one, unambiguous representation. Duplication causes maintenance nightmares.
- **Tracer Bullets** — Build a thin, working version end-to-end before polishing any part. Confirms that all pieces connect before you invest in any one piece.
- **Broken Windows** — Small problems ignored grow into large ones. Fix bad code, bad habits, and bad patterns immediately — don't let them normalize.
- **Your Knowledge Portfolio** — Treat skills like financial investments: diversify, invest regularly, and review what's becoming obsolete.
- **Pragmatic Programmer vs. Perfect Programmer** — The goal is working, maintainable software shipped on time — not theoretical perfection.

**Gaps / Weaknesses:** Assumes a professional software context — some advice (e.g., team dynamics, project management) is less relevant for solo learners. Some chapters feel dated despite the anniversary revision.

- DRY principle connects to [[Functions]] — functions are how you implement DRY in code

- Knowledge Portfolio connects to Kumu's curriculum approach and the Skill Tree system
